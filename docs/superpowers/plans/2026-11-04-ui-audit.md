# UI Audit Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the 2026-11-04 UI audit findings: unsafe input and paste, state that outlives a broker switch, keys acting on the wrong pane, publish-form data loss, width and theme rendering bugs, missing feedback, and help/hint gaps.

**Architecture:** Every fix lands in the TUI crate (`crates/mqtt-zapp/src/tui/`), except two small core helpers in `mqtt-zapp-core/src/payload.rs` (`is_unsafe_char`, CRLF handling in `pretty_lines`). No new dependencies. Each task is one finding group, with its own tests, and commits on its own. Tasks 1–9 are correctness and safety; tasks 10–15 are rendering, feedback and copy.

**Tech Stack:** Rust 2024, ratatui 0.29, crossterm 0.28 (`event-stream`), tui-textarea 0.7, unicode-width 0.2.

**Spec:** The UI audit given in-session on 2026-11-04 (three read-only reviews: rendering, interaction/state, completeness; each item re-checked against the code). Each task below quotes its findings. Read it with `docs/superpowers/specs/2026-11-03-mqtt-zapp-design.md` (scale: hundreds to low thousands of topics).

**Baseline:** The publish-form work (docked form, raw/json/xml, ctrl-o, drafts, preview folding) is uncommitted in the working tree when this plan was written. Commit it first as `feat(tui): dock the publish form, add payload format and leave/return`; every line number below refers to that tree.

## Global Constraints

- Edition 2024. No `unsafe` in non-test code. No new dependencies (musl build stays static).
- Every string from the broker or the user shown on screen goes through `payload::sanitize`, `one_line`, `single_line` or (new, Task 1) `PublishForm`'s input filter. No control or invisible char ever reaches a buffer cell.
- What the publish form sends is the text as shown. If a broker payload can't be shown exactly, it is refused for re-send, never silently altered.
- Keys shown in any hint, note or help line come from `key_for` (or are fixed form keys listed in `HELP_FIXED`). No hard-coded browse key in copy.
- Note copy is lowercase and terse ("cleared 40 retained", "draft restored"). Separator in copy is ` · `.
- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and `cargo test --workspace` pass after every task.
- Commits use conventional prefixes (`fix(tui):`, `feat(tui):`, `fix(core):`), one per task.
- Test helpers already exist: app tests (`app/tests/mod.rs`) `browse`, `key`, `ctrl_key`, `type_str`, `payload_of`, `publish_one`, `sel`; UI tests (`ui/tests/mod.rs`) `app_with`, `draw`, `text`, `last_line`, `mouse`, `click`.

## Review Focus

1. **Pasted text containing `x`, `y`, `q` or a tab.** It must never run as keys: in browse it is dropped, in a text field it is inserted. Test in Task 2: `paste_in_browse_runs_no_actions`.
2. **A broker payload with ESC or CR re-sent from history.** The form must refuse it with a note, not draw it. Test in Task 1: `resend_refuses_control_characters`.
3. **A broker switch while frozen, charted, diffing, or with payload focus.** The new session starts live, uncharted, tree-focused. Test in Task 3: `broker_switch_starts_live_and_clean`.
4. **The docked form filling the whole message pane (stacked or short terminal).** Tab must never focus a pane that is not drawn. Test in Task 5: `tab_skips_hidden_message_pane`.
5. **A key remapped onto another action's default.** Settings load reports the clash and no hint shows a dead key. Test in Task 9: `override_clashing_with_a_default_is_reported`.
